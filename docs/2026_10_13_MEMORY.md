# A soul's memory in ravel

ravel keeps a soul's memory the way [OptMem](https://github.com/VictorTaelin/OptMem)
does. It uses OptMem's algorithm unchanged and stores the result as a graph
beside the soul's transcripts. This page covers what the memory is, how to read
it, how to build it from a soul's past, and how to check that it is right.

## What the memory is

**Notes.** A note is one line of at most 280 bytes, written whenever the soul
learns something new or something worth keeping happens. In OptMem's words,
that covers:

- a task worth real effort;
- a fact or insight the human teaches;
- anything learned about the human's life, even indirectly;
- any event of lasting effect.

The soul does not note what it already holds. Notes are kept in the order they
were written. A note's place in that order is its identity: `#0`, `#1`, `#2`,
and so on.

**Merges.** Neighbouring notes are merged into one line, then neighbouring
merges, all the way up a binary tree:

- `#0-1` merges notes 0 and 1, and `#2-3` merges notes 2 and 3.
- `#0-3` merges those two, `#0-7` merges two of those, and so on.

Neighbours are always merged by position, never grouped by topic or by date.
A block of up to 16 notes is merged from the notes themselves; a bigger block
is merged from its two halves. A merge is made as soon as its notes exist,
with OptMem's instruction word for word: *Compress memories into one line of
at most 280 bytes. Keep what has lasting effect, drop what does not. Invent
nothing.*

**Wake.** When the soul starts, it reads its whole memory in at most 96 lines.
Recent notes are shown word for word, and older ones through their merges.
OptMem chooses the lines so that detail fades with age.

**The graph.** Every note and every merge is a `ravel:Memory` node in the
soul's store, in the named graph `https://repolex.ai/ravel/NamedGraph/memory-v1`.
A note is linked to each conversation turn it rests on, and a merge is linked
to its two halves. Every link uses the one property Subtexture uses
everywhere, `git-lex:relatedToId`. From any line you can walk down to the
words that were actually said.

## Reading it

```sh
ravel memory                # wake: the whole memory in at most 96 lines
ravel memory open 16-31     # a merge, opened into its two halves
ravel memory open '#12'     # a note, with the turns it rests on
```

The lines are in OptMem's own format: `#12 2026-04-04 text` for a note, and
`#16-31 text` for a merge.

## Building it from a soul's past: `ravel-relive`

A soul's past was not written down as notes at the time. `ravel-relive`
relives it instead:

1. It reads every turn the soul has, from Claude Code, Antigravity and the
   Claude desktop app, as one timeline in time order.
2. It works a stretch at a time, about 24,000 characters of conversation.
3. At the start of each sitting it wakes the soul with its memory as it stood
   at that moment.
4. It notes what the soul would have noted.
5. It makes every merge that came due before reading on.

The reader is told it is the soul. It is given the soul's name and its
SOUL.md, and it makes its own merges, as OptMem's agent does.

```sh
ravel-relive plan   <soul-repo> 2000 2100      # how much there is to read; no model calls
ravel-relive dump   <soul-repo> <from> <to>    # exactly what the reader is shown; no model calls
ravel-relive run    <soul-repo> 2000 2100 <soul-repo>/.ravel/_ignore/optmem sub:claude-haiku-5-5+session
ravel-relive verify <soul-repo> <soul-repo>/.ravel/_ignore/optmem
```

`<from>` and `<to>` are the start of a date, compared as text: `2026-09-19`, or
`2026-09-19T04` for a single hour.

**It runs on your Claude subscription.** Each call is `claude -p` with no
tools, no settings and no API key; a call that used an API key is refused.
`sub:<model>` picks the model. `+session` keeps one Claude Code session open
across stretches, the way the soul lived them, and starts a fresh session,
with a fresh wake, once the context passes 90,000 tokens. Calls are made one
at a time.

**It resumes.** A stopped run picks up exactly where it stopped. It never
skips a stretch or a merge, because the tree needs every one.

**What it costs.** Measured on Haiku 5.5 in session mode:

- About 40 stretches an hour.
- The input is mostly re-read from cache: 11.4 million tokens for 41
  stretches of 4RX's busiest day.

`ravel-relive plan` tells you how many stretches a soul has.

### What the reader is shown

`ravel-relive dump` prints exactly what the reader sees. Only the soul's own
life is shown:

- what the soul said;
- what its human said, labelled by name (set `human: Rob` in
  `~/.config/ravel/config.yml`);
- messages from other agents, labelled with the sender's name.

Left out:

- tool calls and their output;
- private thinking;
- compaction summaries;
- the transcripts of subagents and workflows. In OptMem a subagent never writes
  memory, because its notes would arrive duplicated and wrong;
- harness records that arrive as if typed by the human: background-task
  notices, slash commands and their output, system reminders, skill bodies,
  and interruption markers.

A message another agent sends through herdr arrives as plain input, with no
mark on it. ravel finds who sent it from the sender's own transcript: the
`herdr agent prompt` command that sent it, matched by text and time. When
herdr types a message in while the human is typing, the turn is labelled as
both.

## Checking it: `ravel-relive verify`

`verify` checks a memory end to end, and exits with status 1 on any failure:

- every note and merge is one line within 280 bytes;
- every merge that is due has been made;
- every note cites turns from the soul's own stream;
- the wake is exactly OptMem's choice of lines;
- the graph loads, and every link from a merge lands on a node;
- every cited turn exists as a Turn in the soul's store.

The match with OptMem itself is tested in `tests/optmem_conformance.rs`. The
test runs OptMem's own program beside ravel and requires the same bytes for
every merge prompt and every wake:

```sh
OPTMEM_MEMO=~/repos/VictorTaelin/OptMem/memo \
  cargo test --release --test optmem_conformance -- --ignored
```

## Which model spoke each turn

Every turn in a soul's store records the model behind it, so you can ask which
model a soul was running on any day:

- `ravel:model` is the model a Claude Code reply reports. The API writes it on
  every reply, so it is the model that actually answered.
- `ravel:modelSetting` is Antigravity's model setting. Antigravity does not name
  a model on its replies; it announces each change of setting, and ravel carries
  the last one forward through the conversation.
- Claude desktop history names no model, so those turns have neither.

```sparql
PREFIX ravel: <https://repolex.ai/ontology/ravel/>
SELECT ?model (COUNT(?t) AS ?turns) (MIN(?ts) AS ?first) (MAX(?ts) AS ?last)
WHERE { GRAPH ?g { ?t ravel:timestamp ?ts .
  { ?t ravel:model ?model } UNION { ?t ravel:modelSetting ?model } } }
GROUP BY ?model ORDER BY ?first
```

## Where it lives

```
<soul>/.ravel/_ignore/optmem/
  memories.jsonl    the notes, in order: OptMem's log
  summaries.jsonl   the merges, one per line, keyed like `16-31`: OptMem's tree
  extracted.tsv     the turns already read
  dropped.tsv       anything refused, and why
  usage.tsv         tokens used by each model call
```

`raveld` never calls a model. On each of its passes it projects every soul's
memory into the graph.
